# Анализ динамики тем в социальной сети: поиск опережающих сигналов

*Исследовательский проект школьного уровня.*

---

## 1. Постановка задачи

В социальной сети ежедневно появляются тысячи новых постов. Они посвящены разным темам: одни темы существуют годами, другие быстро вспыхивают и угасают, третьи постепенно набирают популярность. Если внимательно следить за динамикой, иногда можно заметить, что тема начинает «разгоняться» ещё до того, как она становится массовой.

В экономике для подобных ситуаций есть понятие — **опережающий индикатор** (leading indicator). Это величина, изменение которой происходит раньше, чем изменение того, что нас в действительности интересует. Классические примеры: количество новых заказов на товары длительного пользования меняется раньше, чем валовой внутренний продукт; индекс потребительских ожиданий меняется раньше, чем розничный товарооборот. Если такой индикатор найден и устойчив, по нему можно прогнозировать.

Вопрос исследования: **существует ли в динамике тем социальной сети измеримый ранний сигнал, по которому можно предсказать предстоящий рост темы за несколько недель до того, как он становится очевидным?**

Гипотеза: такой сигнал существует, и его можно обнаружить, измеряя ускорение роста темы. Когда тема только зарождается, её абсолютные показатели ещё малы, но изменение скорости роста уже происходит — и происходит раньше, чем сам рост становится массовым.

Чтобы проверить гипотезу, нужно:

- собрать данные о постах за достаточный период;
- определить, какие темы в этих постах присутствуют;
- измерить активность каждой темы по неделям;
- описать динамику каждой темы математически;
- найти случаи, когда раннее изменение ускорения предшествовало последующему росту;
- оценить, насколько надёжно работает этот сигнал.

## 2. Данные

Для исследования нужен датасет постов из социальной сети с указанием времени публикации. Подойдут открытые датасеты Reddit, Hacker News, Twitter, доступные на Kaggle или через API соответствующих сервисов. Конкретный выбор не принципиален — важны три свойства датасета:

- достаточный объём (несколько тысяч постов);
- достаточный временной охват (хотя бы полгода, лучше год и больше);
- наличие точных временных меток.

После загрузки данные подготавливаются: посты группируются по неделям, для этого временная метка каждого поста округляется до начала календарной недели. В дальнейшем анализе **неделя** будет основной единицей времени.

Если в датасете тысячи постов, имеет смысл сделать пилотную выборку — взять, например, первые 1000 постов и отладить на них весь процесс анализа, прежде чем запускать полный объём.

## 3. LLM как инструмент анализа

Ключевая методологическая идея проекта: **большая языковая модель (LLM) используется как измерительный инструмент**. Не как генератор текста и не как чат-бот, а именно как инструмент, который по запросу возвращает численные оценки свойств текста.

LLM применяется в двух ролях.

### Роль 1: классификатор

LLM читает пост и определяет, какие темы в нём затрагиваются. Темы не задаются заранее — модель формулирует их сама на основе содержания. Это принципиально: список тем не выбирается исследователем, а *возникает* из данных. Если бы темы задавались вручную, анализ был бы подогнан под предвзятый список. При динамическом извлечении такой подгонки нет.

Школьник пишет промпт самостоятельно. Принципы хорошего промпта:

- чёткая формулировка задачи;
- ограничение на формат ответа (например, список тегов через запятую, без объяснений);
- единый стиль именования тегов, чтобы потом их было легче сравнивать.

Каждый пост прогоняется через LLM, в результате получается набор тегов для каждого поста.

### Промежуточный шаг: нормализация словаря тегов

После первого прохода в данных будут синонимы и варианты: `mobile_security`, `phone_security`, `smartphone_safety` могут означать одно и то же. Чтобы анализ не разваливался на близкие, но формально разные теги, школьник делает второй прогон: отдаёт LLM весь полученный список уникальных тегов и просит сгруппировать синонимы под общими каноническими именами. Полученное отображение применяется к данным — все варианты заменяются на канонические теги.

После этого шага у каждого поста есть список из канонических тегов.

### Роль 2: измеритель

Теперь для каждой пары (пост, тег из тегов этого поста) LLM оценивает, насколько глубоко пост посвящён этой теме. Это число от 0 до 1: ноль означает «упомянуто вскользь», единица — «пост полностью об этом». Получаемое значение будем называть **семантическим весом** и обозначать `w_sem`.

w_sem — это не индикатор присутствия (0 или 1), а непрерывная величина. Слабая ассоциация даёт малое значение, сильная — большое. Это и есть отличие LLM-измерителя от наивного подсчёта по ключевым словам: измеряется не факт упоминания, а *плотность* связи между постом и темой.

### Ограничения метода

LLM не идеально согласованна. Если прогнать тот же пост через ту же модель дважды, оценки могут немного отличаться. Это можно проверить эмпирически: взять небольшую подвыборку и сделать повторные прогоны, посчитать, насколько устойчивы w_sem. Чем меньше разброс — тем надёжнее результаты дальнейшего анализа.

Результаты этой проверки обязательно нужно включить в работу, не пряча их. Если согласованность плохая, нужно либо уточнить промпт, либо использовать усреднение нескольких прогонов, либо честно зафиксировать ограничение.

## 4. Структура данных

После трёх проходов LLM получается следующее:

- **Посты**: id, текст, время публикации, неделя.
- **Теги**: список канонических имён.
- **Назначения**: для каждой пары (пост, тег) — значение w_sem.

Это можно хранить как три таблицы (например, pandas DataFrame) или как граф в Neo4j Community Edition — на выбор. Для школьной работы хватает таблиц. Если хочется поработать с графовой базой данных, схема простая:

- узлы: `Post`, `Tag`, `TagAssignment`, `Week`;
- связи: `Post → TagAssignment → Tag`, `Post → Week`, `TagAssignment → Week`.

В работе схему имеет смысл нарисовать — это помогает читателю и самому исследователю.

Дополнительно стоит сделать простой исследовательский обзор: сколько всего тегов получилось, сколько постов, какие теги самые массовые по числу постов. Это даёт понимание датасета, прежде чем переходить к анализу.

## 5. Масса темы

Имея w_sem для каждой пары (пост, тег), можно посчитать **массу темы в неделю** — суммарный вклад всех постов недели в данную тему.

Формула:

```
M(тема T, неделя t) = сумма w_sem(пост P, тема T) по всем постам P, опубликованным в неделю t
```

Если в неделю t было 10 постов про тему T, каждый со средним w_sem порядка 0.5, то масса темы за неделю — около 5. Если в другую неделю было 3 поста с w_sem около 0.9, масса — около 2.7. Видно, что масса учитывает и количество постов, и глубину связи каждого поста с темой.

Для нескольких выбранных тем строится график зависимости массы от недели. Это и есть первое представление о том, как темы развиваются во времени.

В этой же главе уместно показать общий обзор: какие темы в датасете самые «массивные» (по сумме массы за весь период), как их масса распределена. Это даёт представление о структуре дискуссии в выбранной соцсети.

## 6. Анализ сырых данных

Имея графики массы по неделям, можно попробовать работать с ними напрямую — без всяких дополнительных преобразований. Это полезный шаг: он показывает, в чём именно проблема сырых данных и зачем нужны дальнейшие методы.

Школьник пробует:

- визуально находить закономерности на графиках разных тем;
- считать приросты массы от недели к неделе как простейший показатель динамики;
- сравнивать темы между собой.

На графиках обнаруживаются несколько проблем.

**Шум.** Масса прыгает от недели к неделе хаотично. Один популярный пост, попавший в неделю случайно, делает большой всплеск. Реальная тенденция за этими прыжками не видна.

**Несравнимость пиков.** Тема массивная (массой 50) и тема нишевая (массой 2) имеют графики разной величины, и их «всплески» означают разное.

**Сложность интерпретации приростов.** Прирост ±1 для массивной темы — это шум. Тот же прирост ±1 для нишевой темы — это удвоение. На сырых данных это эмпирически неотличимо.

Главный вывод этой главы: **с сырыми данными работать неудобно**. Чтобы продвинуться, нужно навести в данных порядок — убрать шум и привести величины к виду, удобному для математического анализа.

## 7. Сглаживание

Шум во временном ряду — это случайные краткосрочные отклонения, наложенные на основную тенденцию. Если их отфильтровать, тенденция станет видна.

Простейший метод сглаживания — **скользящее среднее**. Вместо значения массы в неделю t берётся среднее значение массы за окно из нескольких недель, центрированное на неделе t.

Формула (для окна шириной 2k+1 недель):

```
M_сглаж(t) = (M(t−k) + M(t−k+1) + ... + M(t) + ... + M(t+k)) / (2k+1)
```

Школьник пробует разные размеры окна (например, 3, 5, 7 недель) и сравнивает результаты. Слишком узкое окно почти не убирает шум. Слишком широкое — гасит и тенденцию вместе с шумом, реальные изменения становятся «размазанными» по времени.

После сглаживания графики масс становятся гораздо чище. Видны устойчивые периоды роста, плато, спады. Шум убран, остаётся структура.

Сглаживание выполняет двойную функцию: оно убирает шум, и одновременно приводит ряд к виду, который удобно дифференцировать (это понадобится дальше). Несглаженный ряд дифференцировать бессмысленно — разностные производные будут полностью забиты шумом.

В этой же главе обсуждается выбор размера окна как методологическое решение: слишком маленькое — шум остаётся, слишком большое — теряется реальная динамика. Размер окна — это компромисс, и его выбор должен быть осознанным.

## 8. Темпоральный вес и накопительный индекс

До сих пор масса темы измерялась независимо в каждой неделе: посты из недели t влияют только на M(t). Но на самом деле тема — это не разрозненный набор еженедельных всплесков, а *непрерывный процесс*. Если на этой неделе по теме появилось много постов, тема «жива». Если на следующей неделе постов нет — это не значит, что тема мгновенно исчезла. Накопленный интерес сохраняется и затухает постепенно.

Идея: построить **накопительный индекс темы** I(t), который ведёт себя естественно:

- когда по теме идут новые посты, индекс растёт за счёт прибавления новой массы;
- когда новых постов нет, индекс не обнуляется, а постепенно затухает.

### Активная и неактивная фазы

В каждую неделю t тема находится в одной из двух фаз:

**Активная фаза** — в неделю t есть посты по теме, то есть M(t) > 0. Индекс растёт за счёт прибавления новой массы:

```
I(t) = I(t−1) + M(t)
```

Накопленный индекс хранит память обо всём, что было раньше, и пополняется свежим вкладом этой недели.

**Неактивная фаза** — в неделю t новых постов по теме нет, M(t) = 0. К накопленному значению применяется **темпоральный вес** — множитель меньше единицы, который уменьшает индекс:

```
I(t) = темпоральный_вес · I(t−1)
```

Тема не забывается мгновенно, но и не остаётся вечно. С каждой неделей бездействия накопленная масса теряет часть своего значения.

### Форма темпорального веса

Самый естественный выбор — экспоненциальное затухание:

```
темпоральный_вес = e^(−α)
```

где α — параметр, задающий скорость затухания.

Тогда в неактивной фазе:

```
I(t) = e^(−α) · I(t−1)
```

Если тема молчит несколько недель подряд, накопленный индекс через k недель бездействия равен:

```
I(t+k) = e^(−α·k) · I(t)
```

То есть в фазе релаксации индекс убывает по чистой экспоненте, начиная от того значения, которое накопилось к моменту последнего упоминания.

Конкретные значения α определяют скорость затухания:

- α = 0.1: за неделю индекс сохраняет 90% значения, за месяц — 67%, за полгода — 7%.
- α = 0.3: за неделю — 74%, за месяц — 30%, за полгода — почти ноль.
- α = 0.5: за неделю — 61%, за месяц — 14%.

Школьник пробует несколько значений α и смотрит, как они влияют на форму индекса. Содержательная интерпретация: малое α соответствует долгой памяти (темы помнятся надолго), большое α — короткой (темы быстро забываются).

### Возобновление активности

Если после периода затухания по теме снова появляются посты, индекс снова входит в активную фазу. Новая масса прибавляется к тому значению, которое осталось после затухания:

```
I(t) = I(t−1) + M(t)   при возобновлении активности
```

Это правильно описывает реальное поведение тем. Если тема была популярной, потом утихла, и через месяц возобновилась — индекс не начинает с нуля, он продолжает с того уровня, до которого успел затухнуть. Это и есть «эффект памяти».

### Полная формула накопительного индекса

Обобщая, накопительный индекс строится итеративно по неделям:

```
I(t) = I(t−1) + M(t),           если M(t) > 0
I(t) = e^(−α) · I(t−1),         если M(t) = 0
```

Начальное условие: I(0) = 0 для всех тем, или I(0) = M(0), если в начальной неделе тема уже была активна.

В коде это простой цикл по неделям с проверкой условия.

### Что даёт накопительный индекс

Графики I(t) для разных тем дают новую картину их жизненного цикла:

- Тема стабильно активная — индекс плавно растёт, затухание не успевает заметно сработать между постами.
- Тема всплеска — индекс быстро вырастает в период активности, потом плавно затухает по экспоненте.
- Тема, возобновляющаяся периодически — индекс показывает «гребёнку»: пики роста, чередующиеся с периодами затухания.
- Тема, угасшая окончательно — индекс плавно стремится к нулю.

В отличие от сырой массы M(t), накопительный индекс — гладкая функция (или почти гладкая, потому что в моменты прибавления массы могут быть скачки). Он удобен для дальнейшего математического анализа: можно считать производные, искать характерные точки, описывать форму кривой аналитически.

При желании к итоговому индексу можно дополнительно применить лёгкое сглаживание, чтобы убрать остаточные скачки в моменты возобновления активности. Но и без этого I(t) гораздо мягче исходной массы, потому что темпоральный вес сам по себе работает как фильтр памяти.

## 9. Производные индекса

Чтобы найти опережающий сигнал, нужно перейти от значений индекса к **скорости** и **ускорению** его изменения.

**Скорость** — это первая производная индекса по времени, dI/dt. Положительная — тема растёт, отрицательная — тема затухает.

**Ускорение** — вторая производная, d²I/dt². Это скорость изменения скорости. Положительное ускорение — тема растёт всё быстрее. Отрицательное — рост замедляется или начинается спад.

**Почему ускорение интереснее скорости.**

Представим тему, которая постепенно набирает обороты: пара постов в неделю, потом пять, потом десять, потом двадцать. Когда станет «двадцать постов в неделю», все уже поймут, что тема популярна — но к этому моменту делать прогноз поздно. А когда было «пять постов в неделю», это ещё небольшое число. Зато *рост* числа постов с двух до пяти, потом с пяти до десяти — это значит, что *скорость* увеличивается. Когда скорость увеличивается — ускорение положительное.

Ускорение реагирует *раньше*, чем абсолютные значения становятся большими. Когда массовая публика ещё не заметила тему, ускорение уже сигнализирует: «здесь что-то начинает разгоняться». Именно поэтому ускорение — кандидат на роль опережающего индикатора.

### Как считать производные

Самый простой способ — разность соседних значений:

```
dI/dt ≈ I(t) − I(t−1)
d²I/dt² ≈ скорость(t) − скорость(t−1)
```

Это работает на гладких функциях, но плохо работает на реальных данных. Даже после сглаживания скользящим средним в индексе остаётся остаточный шум. Простая разность этот шум усиливает, а вторая разность усиливает ещё раз. На практике d²I/dt², посчитанная как разность разностей, превращается в зубчатую пилу, в которой настоящий сигнал тонет.

Нужен метод, который одновременно подавляет шум и считает производные. Такой метод существует — **локальная полиномиальная аппроксимация**.

### Локальная полиномиальная аппроксимация

Идея: вместо того чтобы считать разность между двумя соседними точками, посмотрим на участок индекса вокруг точки t и приблизим его гладкой функцией, у которой производные считаются точно.

Конкретно: берём окно из 2k+1 ближайших недель вокруг точки t. Например, при k=3 — это 7 недель: три до t, сама t, три после. В этом окне подгоняем многочлен невысокой степени (обычно 2-й или 3-й) методом наименьших квадратов:

```
I(τ) ≈ a₀ + a₁·τ + a₂·τ² + a₃·τ³
```

Многочлен — гладкая аналитическая функция. Его производные считаются точно по школьной формуле производной многочлена:

```
dI/dt = a₁ + 2·a₂·t + 3·a₃·t²
d²I/dt² = 2·a₂ + 6·a₃·t
```

Значение производной в точке t — это значение производной подогнанного многочлена в этой точке. Окно сдвигается на следующую неделю, для неё строится свой многочлен, и так далее.

**Что это даёт.**

Многочлен не обязан проходить через все точки окна — он подгоняется по методу наименьших квадратов, то есть описывает общую *форму* кривой, игнорируя случайные отклонения. Это и есть сглаживание — встроенное в саму процедуру. Шум подавляется автоматически.

Производные получаются *аналитически* — не как разность шумных численных значений, а как точные производные гладкой подогнанной функции. Это намного устойчивее.

Метод называется **фильтром Савицкого-Голея**. В Python он есть в готовом виде:

```python
from scipy.signal import savgol_filter

velocity = savgol_filter(I, window_length=7, polyorder=3, deriv=1)
acceleration = savgol_filter(I, window_length=7, polyorder=3, deriv=2)
```

Здесь `window_length` — размер окна (нечётное число), `polyorder` — степень многочлена, `deriv` — порядок производной.

Параметры влияют на результат:

- Большое окно — сильнее сглаживание, но теряются быстрые изменения.
- Маленькое окно — слабее сглаживание, остаётся шум.
- Степень многочлена 2 — простая парабола, описывает только однонаправленную кривизну.
- Степень 3 (кубический многочлен) — может описать перегиб, лучше следует за изгибами кривой.

Школьник пробует несколько комбинаций параметров и обсуждает компромисс.

### Проверка метода на синтетических данных

Прежде чем применять метод к реальному индексу, полезно проверить его на функции, у которой производные известны. Например: взять f(t) = sin(t/5) + небольшой случайный шум, посчитать первую и вторую производные через Савицкого-Голея и сравнить с точными производными синуса. Если совпадают — метод работает корректно. Если нет — нужно подобрать параметры.

Это даёт школьнику уверенность, что применяемый инструмент даёт правильные результаты.

### Дополнительно: сравнение с глобальной аппроксимацией

Локальная аппроксимация подходит для тем любой формы. Но для некоторых тем форма кривой явно простая — например, тема с одним всплеском похожа на колокол, а тема с насыщением похожа на S-образную (логистическую) кривую. Для таких тем можно подогнать *глобальную* аналитическую функцию ко всему ряду:

- Гауссиана: I(t) = A · exp(−(t−μ)²/2σ²) для тем с одним симметричным пиком.
- Логистика: I(t) = K / (1 + exp(−r·(t−t₀))) для тем с S-образным ростом.

Параметры A, μ, σ или K, r, t₀ подгоняются методом наименьших квадратов на полных данных. Затем производные считаются аналитически по формулам производных этих функций.

Это даёт второй, независимый способ посчитать производные. Если результаты Савицкого-Голея и глобальной аппроксимации согласуются для тех тем, к которым подходит глобальная форма — это подтверждает корректность обоих методов. Если расходятся — интересно разобраться почему (обычно глобальная форма не идеально описывает реальную кривую, и Савицкий-Голей точнее следует за фактическим поведением).

Этот шаг не обязателен, но усиливает работу: школьник показывает, что метод не выбран наугад, а проверен на сравнении с альтернативой.

### Графики

Для нескольких выбранных тем строятся три графика друг под другом:

- сам индекс I(t);
- скорость dI/dt;
- ускорение d²I/dt².

Хорошо видно, как пики ускорения предшествуют пикам индекса. Это качественное подтверждение того, что ускорение действительно может быть опережающим индикатором — но количественная проверка делается в следующей главе.
